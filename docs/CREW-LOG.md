## 2026-09-24 P4 Motion Engineer, Batch 2 live-mount fix (Sonnet 5)

Lead's review of the live desktop mount (`src/components/desktop/OrbitBand.tsx`, `.orbit-slot` 640x360) found half-cut logos along the panel's bottom and guide arcs too faint under grain.

- Investigated on the real site (localhost:3000, band at ~y960 on 1440x900) before changing anything: `getComputedStyle` confirmed `.orbit-panel`/`.orbit-panel__body`/`.orbit-fan` all compute `overflow:hidden` with the fan's height exactly 316px (desktop `cy`), and a live animation check confirmed the rings genuinely are mid-spin (`animationName:"orbit-ring-cw"`, a non-identity transform matrix), not frozen. Root cause wasn't a missing or broken clip, it's that "linear infinite rotation" means every ring sweeps a full 360deg, so every chip passes behind the horizon once per cycle (same as the measured reference); a hard `overflow:hidden` clip alone slices whichever chip is mid-crossing into a flat-edged half-circle at that instant, which reads as a bug even though nothing paints past the line. - Decided: added a CSS mask (`-webkit-mask-image`/`mask-image: linear-gradient(to bottom, #000 0%, #000 85%, transparent 100%)`) to `.orbit-fan`, feathering the last 15% of the stage into transparent so a chip dissolves as it nears the horizon instead of getting sliced; `overflow:hidden` stays underneath as the hard backstop so nothing ever paints past the true line. No structural change to `.orbit-fan`'s height/positioning, which was already correct.
- Decided: `.orbit-guide-arc` moved from `--luna-300` at 0.45 opacity (ART-DIRECTION 7.3's literal value) to `--luna-400` at 0.7, per the lead's direct instruction after live review found the documented value nearly invisible under the real grain layer; an explicit, recorded override of the doc, not a silent drift.
- Verified: a literal DOM bounding-box assertion ("no chip's bbox extends below the line") would trivially fail for a rotating element under a CSS clip, since `getBoundingClientRect`/Playwright's `boundingBox()` report geometry, not paint clipping, so some chip is always geometrically "below the line" mid-rotation regardless of whether anything is visible there.
